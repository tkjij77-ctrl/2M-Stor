## 3) لوحة التحكم الجديدة

**الطريق:** زر «🖥️ لوحة التحكم» في الهيدر · أو قائمة ☰ ← «لوحة التحكم الاحترافية».

| الشاشة | ماذا تفعل |
|---|---|
| 🏠 الرئيسية | طلبات جديدة بانتظار التأكيد · مبيعات اليوم · جراف آخر 7 أيام · الأصناف الناقصة · أحدث الطلبات · إجراءات سريعة |
| 🧾 الطلبات | تصفية بالحالة مع عدادات + بحث برقم/اسم/هاتف + صفحة تفاصيل لكل طلب |
| 📄 تفاصيل الطلب | مسار الحالة · اتصال `tel:` · واتساب · العنوان والملاحظات · صورة الإيصال · أزرار: تأكيد ← خرج للتوصيل ← تم التسليم ← إلغاء · طباعة |
| 📦 المنتجات | بحث وفلترة كاملة + تبديل توفر فوري + سعر قبل الخصم + وصف + حتى 8 صور مع اختيار الغلاف |
| 📂 الأقسام | إضافة/تسمية/صورة دائرية/ترتيب بالأسهم (بدل `prompt()`) |
| 🖼️ البنرات | إضافة/تعديل/إخفاء/ترتيب بنرات السلايدر وربطها بقسم أو منتج أو رابط |
| 👥 العملاء والصلاحيات | تغيير الأدوار + مفاتيح صلاحيات العامل والعميل |
| ⚙️ إعدادات المتجر | فتح/إغلاق المتجر · الشعار · لون الهوية · شريط الإعلان · فودافون كاش/إنستاباي/بنك · الشحن والضريبة والكوبون |

### 🔍 وضع المعاينة (مهم)
`index.html?preview=admin` يفتح اللوحة بصلاحية مدير **بدون تسجيل دخول** لتجربة الواجهة:
- ✅ يقرأ كل البيانات الحقيقية.
- 🚫 **لا يكتب شيئًا على السحابة إطلاقًا** (كل الدوال تمر عبر `proQueueSafe` الذي يمنع الكتابة في المعاينة).
- زر «إنشاء طلب تجريبي» في شاشة الطلبات يبني طلبًا **محليًا فقط** لتجربة الشاشة.

## 4) رحلة العميل (Checkout)

1. العميل يضيف للسلة → يرى **شريط الشحن المجاني**.
2. يضغط **«💳 إتمام الطلب أونلاين»** في السلة.
3. ثلاث خطوات: البيانات (الاسم + موبايل `01xxxxxxxxx`) → التوصيل/الاستلام → طريقة الدفع (مع رفع صورة إيصال التحويل).
4. يُستدعى `place_store_order()` على السيرفر:
   - يعيد حساب **كل الأسعار والشحن والكوبون والضريبة من قاعدة البيانات** (سعر المتصفح لا يُوثق به).
   - يقفل صف الصنف (`for update`) ويمنع بيع القطعة لعميلين في نفس اللحظة.
   - يخصم المخزون في نفس المعاملة.
   - يرفض: متجر مغلق · رقم غير صحيح · عنوان ناقص · تحويل بلا إيصال · أكثر من 8 طلبات/ساعة لنفس الرقم.
   - يُرجع `order_no` + **رمز تتبّع** سرّي.
5. العميل يرى شاشة نجاح + زر **تتبّع الطلب** + رابط يُنسخ ويمكن فتحه لاحقًا: `index.html?order=<token>`.
6. لو السحابة غير متاحة (أوفلاين) — الطلب يُحفظ محليًا مع زر إرسال على واتساب، **فلا يضيع أي طلب**.

## 5) الإعدادات التي يجب ضبطها من لوحة التحكم

| الإعداد | لماذا |
|---|---|
| **رقم الهاتف / واتساب** | فارغ حاليًا! بدونه لا يعمل زر واتساب ولا الاتصال بالعميل |
| **مصاريف الشحن / حد الشحن المجاني** | كانت غير محفوظة في القاعدة (التطبيق كان يفترض 20/200) — صارت الآن 20/200 صريحة وقابلة للتعديل |
| **العنوان** | يظهر للعميل في خيار «استلام من المحل» |
| **فودافون كاش / إنستاباي** | بدونهما يظهر للعميل خيار «الدفع عند الاستلام» فقط |
| **شريط الإعلان** | نص قصير يظهر أعلى المتجر لكل الزوار |
| **لون الهوية والشعار** | يغيّران مظهر المتجر فورًا |

```bash

# 2) نشر الدالة
supabase functions deploy telegram-order-bot --no-verify-jwt

# 3) ضبط الـ webhook
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://uzzxhbotbshsgpdnbrmd.supabase.co/functions/v1/telegram-order-bot"

# 4) في لوحة Supabase → Database → Webhooks:
#    جدول invoices · الأحداث INSERT و UPDATE · POST إلى نفس الرابط
```

## 8) الأمان — ما تغيّر بالضبط

| البند | التفصيل |
|---|---|
| كتابة الزائر | **لا تُفتح أي جدول للكتابة العامة.** الطلب يمر بدالة `SECURITY DEFINER` واحدة تتحقق من كل مُدخل |
| الأسعار | تُحسب على السيرفر فقط — تعديل سعر في المتصفح لا يؤثر |
| التتبّع | الرمز 32 حرفًا عشوائيًا · يُخفى الهاتف جزئيًا (`0100****678`) · لا يكشف أي طلب آخر |
| الإغراق | حد 8 طلبات/ساعة لنفس الرقم + حد 60 صنفًا و200 قطعة للطلب |
| الإيصالات | تُرفع إلى Storage ثم يُرسل الرابط فقط |
| تيليجرام | `order_chat_links` **ممنوع تمامًا** على `anon`/`authenticated` (revoke كامل) |
| CSP | أُضيف `https://telegram.org` لسكربت الميني-آب فقط |
